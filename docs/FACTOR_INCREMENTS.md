# 多因子引用与增量贡献

迭代011，2026-10-20（Asia/Shanghai）。入口 `/increments`，导航“多因子增量与引用”。应用仍只依赖Python标准库。

## 操作

1. 在工作台准备月度快照与因子版本。多因子页选择2至10个非组合版本，填写正权重、名称和理由，保存不可变版本；可选父版本。原工作台的多选列表是逐窗择优，不是加权合成。
2. 在工作台仅勾选新组合版本，运行基线实验。组合版本也可用作现有组合回放的固定打分规则；这不赋予组合独立最终验收资格。
3. 回到多因子页，选择当前引擎开发实验、其明确绑定的一个原组合/固定因子、库中的新增非组合候选及1%至99%的候选占比。提交后台增量评估；源实验若包含多个候选，本页仍按选定原版本重算，绝不沿用逐窗获胜因子。
4. 比较原组合、候选单因子、加入后组合的上涨比例、平均扣费收益、最差单笔、样本量与选股重合率。查看每个成分被移除后的差值，以及分年和测试块稳定性。加入后的不可变组合已留库，可在工作台作为唯一版本重新实验。
5. 导出完整本地JSON或复现固定请求。版本引用区可查询成分对应的多因子版本、派生版本、实验、冻结、组合版本及增量报告；修改不会改写历史绑定。

页面沿用TaskWatcher的观察版本和轮询序号保护；报告详情另有请求序号。手机端长版本号换行，表格在容器内滚动。队列任务类型为第六种 `increment`，支持取消、超时、新建重试和启动中断；不支持暂停续算。关闭页面不会取消任务，任务页同样可查看和控制。

## 定义和计算

- `blend` 保存成分的完整不可变定义、ID和权重。成分必须为非blend因子（参数/公式或旧四因子combined均可），最多10项，同一版本不可重复；不允许嵌套。旧combined仍按旧定义计算，本页不把它伪装成可分别归因的四个版本。
- 用户权重是 `.000001` 至 `1000000` 的有限正数。每个信号截面，各成分先转平均秩百分位 `(平均秩-1)/(N-1)`，同分共享百分位；再按归一化权重加权。分数不是概率或历史分位。
- 权重同时存显示数值与精确有理数 `ratio=[分子,分母]`。百分位和加权在Fraction中计算，最后转浮点分数，避免加入/移除时的归一化误差破坏原组合相对权重及同分排序。不拟合权重，不利用未来标签。
- 候选占比w固定时，原成分归一权重乘 `(1-w)`，新增成分占w。逐项移除后，剩余精确权重重新归一。若只剩一个成分，直接使用该版本的分数；Top K排序与其百分位相同。
- Top K同分时按股票代码升序，固定选择K只；这与诊断分组的“不拆同分”是两个不同用途。输入或公式错误拒算整个配对截面，不补零、不删股，不为不同版本移动测试起点。

## 配对协议与解释边界

评估从源实验快照直接截取 `date < holdout_start` 的开发数据，与诊断共用 `development_data`。仅使用源实验实际成熟、按持有期间隔的非重叠测试信号窗；不加入训练窗或最终留出。

所有版本采用同一股票池、信号日、下一观察点入场、持有期、退出日、Top K和往返成本。单笔净收益为退出值/入场值−1−成本，按股票×窗口等权统计，不年化、不复利。差值均为“加入后−原组合”或“完整组合−移除后”，各段同时报告样本数量。缺失时保留原因，仅在共同成功窗口统计，**任何窗口缺失均使 `comparison_eligible=false`，不能判为改善**；全部缺失时指标和差值为null。

决策复用源实验结构化目标和均值/尾部/样本门槛。候选单因子表现好不代表加入后改善，负贡献和未通过同样留档。移除贡献不可相加，不是因果证明；重复搜索开发窗有选择偏差，没有显著性、多重检验校正、行业控制或真实效果保证。

这不是持仓/资金净值归因，也不提供权重优化、动态股票池或公司行动处理。价格收益不含分红且未调整除权跳变；合成和来源声明保留。固定多因子可以作为既有单笔冻结流程的一个打分版本，仍须独立验收与人工判断，不能据此启用组合交易。

## AI增量模式

研究室新增 `research_mode=augment`，保留默认 `replace`。增量模式基线实验必须只绑定一个固定因子或多因子版本，原成分最多9个；创建会话时冻结候选占比。

每轮ChatGPT/DeepSeek仍仅提出现有JSON契约中的一个公式。系统创建公式版本，再把它以冻结权重加入**原基线**组成新版本，运行固定版本实验，并用增量报告交叉核对指标和窗口覆盖。比较当前最佳与原基线，且满足额外约束后才能更新研究最佳；下一轮再次检验一个新的添加方案，不是把每轮候选累加。公式父版本保留提出时的当前最佳来源，新组合父版本始终为固定原组合。

手动协作包及OpenAI/DeepSeek API每轮获得组成定义、增量汇总和逐项移除差值；当前最佳若有增量报告也进入下一轮上下文。内部 `get_factor_increment(experiment_id)` 只接受当前增量会话内的候选实验，核对原组合、候选、权重、引擎和完整绑定。原始行情、逐股收益/选股与留出收益不进入模型；API再次白名单裁剪。暂停恢复沿用既有请求/预算规则，未知调用不自动重发；不自动启用版本。

跨会话试验统计新增 `increment_reports` 和 `increment_jobs` 及各自状态：手动与AI产生的不可变报告另计，队列重放新增任务但缓存命中不新增报告。AI候选实验仍计入原收益实验；两者不能相加后称为独立试验数。多因子结构重复签名纳入成分计算定义与归一化精确权重，版本名称、顺序或同比缩放不掩盖相同计算定义。

## API和存储

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| POST | `/api/increments/blends` | `components:[{factor_id,weight}],name,reason,parent_id?`；保存不可变factor |
| POST | `/api/increments/reports` | `experiment_id,base_factor_id,candidate_factor_id,candidate_weight?`；可加时限，返回任务 |
| POST | `/api/increments/reports` | 仅 `replay_id`，可加 `timeout_seconds`；不能与新参数混用 |
| GET | `/api/increments/reports` | 结果索引，包含失败，不带大型正文 |
| GET | `/api/increments/reports/{id}` | 完整固定报告，包含本地逐窗选股与收益 |
| GET | `/api/increments/references/{factor_id}` | 本地版本引用关系 |

新增纯计算 `increments.py` 与服务 `increment_service.py`。`factor_increment` ID由固定请求及引擎摘要生成，同请求返回已有不可变结果；请求形状/版本校验失败在提交时拒绝，接受后的计算失败留报告。结果不含会变动的全局试验计数，实时计数另行查询。无需数据库迁移；停机备份整个数据目录。引擎更新后旧实验/暂停会话不能跨版本继续，需要重跑基线或恢复原代码环境。
