# 因子诊断与跨会话试验统计

迭代009，2026-10-16（Asia/Shanghai）。入口 `/diagnostics`，从工作台、研究室、行情、验证或组合导航进入。零新增应用运行依赖。

## 使用

1. 在工作台完成当前引擎的开发实验。旧结果可查看，但代码摘要改变后需要按原参数重新实验才能新建诊断或AI会话。
2. 在“因子诊断”选择源实验、1至10个因子和2至10组（不超过池内股票数），提交后台任务。默认选择源实验因子，也可诊断库中其他版本；这是额外开发尝试，不构成新的独立验收。
3. 查看覆盖率、IC、分组、相关性与分年/测试块稳定性；展开各窗口核查空值和输入失败原因。导出完整JSON。相同参数与引擎复现返回同一个不可变报告，任务仍新增，保留执行历史。
4. 在“跨会话试验记录”选择整个数据目录或所选实验同协议，核查收益实验、已消费候选、重复与未完成记录，并可另行导出当次台账JSON。
5. 研究室的手动协作包和OpenAI/DeepSeek API上下文自动附开发诊断摘要及同协议尝试计数；每个成功候选实验的反馈也附相对原基线首因子的诊断，未获准入的候选同样保留。诊断不修改现有目标/均值/尾部准入，不自动启用版本。

新任务类型 `diagnostic` 复用单工作进程队列、取消、超时、重启中断、新建重试，不支持暂停续算。关闭页面不取消任务；任务页同样可控制。输入请求错误在提交时拒绝，已接受后的计算失败保存失败报告。全部因子都缺失/不可计算时，报告本身仍可成功生成，但分值覆盖为0，不代表因子有效。

## 数据边界与固定窗口

报告绑定源开发实验、数据快照、因子版本、组数和引擎。仅解析快照中 `date < holdout_start` 的开发面板，不读取最终留出收益；测试信号、持有期、延迟入场和费用采用源实验的实际开发测试窗口。

每个信号日 i 用截至 i 的因子输入计算分数，下一月观察点 i+1 入场，i+1+h 退出。使用源实验按h月间隔的非重叠测试信号窗，不把训练窗或每月重叠标签混入IC。每个测试块保留相同信号窗，不因某个因子缺失而悄悄移动起点。候选最大历史需求仍受原公式语言30月上限与共同预热约束。

报告不是冻结后的最终独立验证，也不承诺参数选择独立于整个开发窗。原始快照仍可由本地用户查看，软件不能识别外部窥视或外部试验。

## 统计口径

| 统计 | 定义与边界 |
| --- | --- |
| 输入覆盖 | 每个信号截面中全部所需当前因子字段非空的股票数 / 应有股票数，再按股票×窗口汇总；不代表公告时点经外部核验 |
| 计算覆盖 | 成功产生完整固定池分值的股票×窗口数 / 应有数；任何输入/表达式错误拒算整个因子截面，不补零、不删股票 |
| Rank IC | 当期分值与成熟净收益的Spearman相关。两向量先取平均秩，再计算Pearson相关；任一向量常数或配对少于3个时为null，不写成0 |
| IC汇总 | 各有效信号窗IC算术平均、总体标准差（至少2个有效窗）、正IC窗比例和有效窗数。等权按窗，不按股票数加权。窗口与横截面有关联，不提供显著性、ICIR、置信区间或年化 |
| 分组 | 股票平均秩r，组桶为 `min(G-1, floor((r-0.5)*G/N))`；1组最低、G组最高。同分进入同组，不按代码拆散，人数不一定相等，部分组可为空 |
| 分组收益 | `退出价格或指数/入场值 - 1 - 往返bps/10000`；按股票×窗口等权算术平均，提供样本数。单窗另有上涨比例与最差单笔；空组返回null |
| 高低组差 | 同一窗最高组均值减最低组均值，再对两端均非空的窗口等权平均；报告有效窗口数。常数因子/并列导致端组缺失时为null；不是可执行的多空收益或组合净值 |
| 时期稳定性 | 按信号日年份、源实验测试块分别汇总上述统计与样本数；不比较不同期限的年化收益。暂无行业数据，不能提供行业中性或行业稳定性 |
| 因子间秩相关 | 同一信号窗两因子分值的Spearman相关，再对双方成功且相关非恒定的共同窗等权平均，同时显示共同成功窗和有效相关窗；常数因子的对角线也可能为null |

覆盖率或有效样本不同的结果不能直接声称改善。报告显示所有因子共同成功截面数；相关矩阵逐对显示共同样本。高相关只能提示冗余，不证明定义重复，也不替代多因子组合的增量贡献测试（A3仍待）。

价格收益继续明确不含现金分红，公司行动跳变未调整；含分红指数与价格口径分开。固定池有幸存者偏差、数据来源/available_at为声明；合成数据只验证计算和流程。

## 跨会话计数与重复

台账在SQLite单个读事务中读取收益实验、会话进度及已消费提案事件，生成带 `as_of` 的即时统计，不覆盖旧实验。全目录统计会包含不同来源/协议；同协议筛选要求快照ID、horizon、top_k、cost_bps、holdout_months、objective及引擎一致，因子列表可以不同。

- 收益实验：每个持久化experiment算一条，状态分列；手动、AI、重放和失败均保留。新诊断任务不计为新的收益实验。
- 结构重复实验：同协议且因子计算定义的有序列表相同（首因子关系有意义），一组n次记录显示n-1次额外重复；名称、理由、父版本不同不掩盖重复计算定义。
- 候选尝试：以会话ID+轮次去重，合并 `proposal` 事件、pending和outcomes；同一轮的事件与结果只算一次。已消费的 propose 包括非法、拒绝、失败和未完成；stop另计，已提交未消费的提案另计。
- 正在运行/排队/暂停的pending记为in_progress，取消等终态的pending记为unresolved_状态；只有提案事件而缺少进度/结果时记为unresolved。不推断其为失败或成功。
- 公式重复：用白名单AST规范形识别空格/括号差异，内置动量/质量/价值/低波动映射为相应原语。非法公式单独计数。重复公式保留每次会话、轮次、状态；跨协议重复不表示表现可直接比较。
- 因子库重复定义与已消费尝试不同：创建了相同定义未运行时，可以出现在全目录的重复因子定义记录中，但不会凭空增加提案尝试数。

重复识别不做代数等价证明（如 `a+b` 与 `b+a`），尝试次数不是独立统计样本，不据此计算虚假显著性；当前不做多重检验校正。未消费草稿、没有落盘的操作、其他数据目录及外部试验不可见。已有任务无新事件时以现有进度为准，缺失无法还原的历史不虚构。

## AI边界与API

内部新增 `get_factor_diagnostics(experiment_id, factor_ids?)`：实验必须属于当前会话，因子必须在会话允许集合；固定快照/协议/引擎检查保留。默认将原基线首因子与指定实验首因子在相同窗口诊断，用于提示冗余。

手动协作包包含覆盖/IC/分组摘要、相关统计和同协议计数；API再次白名单裁剪为覆盖/IC/高低差/相关性/计数。不给模型逐股分数、逐股收益、原始行情、留出结果、其他会话的个别指标或自动启用工具。API调用预算仍在网络请求前预留，新增摘要会占用上下文预算；不足时照常停止，不绕过预算。

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| POST | `/api/diagnostics/reports` | `experiment_id`，可加 `factor_ids,group_count,timeout_seconds`；或仅 `replay_id` 加时限，返回任务 |
| GET | `/api/diagnostics/reports` | 报告索引（不含大型报告正文） |
| GET | `/api/diagnostics/reports/{id}` | 不可变诊断全文或失败原因 |
| GET | `/api/diagnostics/trials` | 当前目录各协议的实时计数与重复关联 |
| GET | `/api/diagnostics/trials/{experiment_id}` | 所选实验相同协议的实时计数 |

新增模块 `diagnostics.py` 为纯计算，`diagnostics_service.py` 为版本/开发窗/队列服务，`trial_audit.py` 为只读试验统计。报告存储仍为本地SQLite artifacts；备份按既有规则停机复制整个数据目录。


## 010：审查与页面状态修复

刷新及后台任务完成时保留当前额外勾选的因子；切换源实验时重新采用该实验默认集合。诊断/组合页共用 `TaskWatcher`，按当前任务观察版本和每次轮询序号丢弃旧响应；研究室详情同样按请求序号保护。旧任务返回不会覆盖新任务、报告或取消目标，取消后的旧状态也不会把按钮重新启用。

试验范围查询独立响应最新选择，不因其他操作忙碌而跳过；加载时清空过期计数并暂禁导出，只有匹配当前范围/实验的最新结果可显示或导出。模型恢复的动态计数规则见[模型API](MODEL_API.md)，不会改变研究输入或准入政策。修复证据见[010](iterations/010-diagnostics-review/README.md)。
