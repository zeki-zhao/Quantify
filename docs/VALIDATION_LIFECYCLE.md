# 目标、最终验证与研究版本

迭代 005 新增 `/strategies`“验证与版本管理”，从工作台、研究室或在线行情页进入。全流程为个人本地研究；此页不产生订单，仍为单笔研究。008另在[组合页](PORTFOLIO.md)提供开发窗现金/持仓/换手/净值，尚未与此页最终验收和启用打通。

## 结构化目标

在工作台创建实验时选择主目标，默认 `positive_rate`（扣费后上涨比例），也可选择 `mean_return`（平均单笔净收益）。同时指定最低主目标改善、均值/最差单笔允许下降及最少样本数。UI 幅度单位为百分点；API 中 1 个百分点填 `0.01`。

```json
{
  "primary": "positive_rate",
  "min_improvement": 0,
  "max_mean_deterioration": 0,
  "max_tail_deterioration": 0,
  "min_observations": 1
}
```

`min_observations` 是软件最低门槛，不是统计显著性标准；默认 1 不足以证明稳定性，实际研究需事先提高门槛并增加独立时间窗口。

同一个 `assess` 政策用于三处：

- 训练：候选列表首项是基线。其余因子相对该项满足主目标严格改善及均值/尾部/样本约束才进入择优；无合格替代者时保留首项。只用标签已成熟的训练数据。单因子实验始终检验该因子。
- 研究室：候选必须分别通过相对“当前最佳”和“原基线”的判定，窗口及单笔样本数一致。沿用基线实验的结构化政策，目标文字不会暗中改变政策；额外均值/尾部门槛只会收紧约束。每轮保存所有检查与失败原因。
- 最终验证：相对预先冻结的参照检查主目标、均值、尾部及样本门槛。参照可为同期全池，或同协议基线实验最后开发窗所选因子。

默认不接受上涨比例持平，即使均值上升。明确选择均值主目标时允许上涨比例下降，但报告仍显示上涨比例，不能称其为胜率改善。因子候选的父版本取当前最佳实验首个因子，后续轮次能够追溯真实演化；多因子版本引用和组合增量诊断仍待实现。

目标已加入实验请求、协议、报告和引擎摘要。不同目标的实验不能直接比较。旧引擎实验仍可查看；新会话需按原数据/参数和所需目标重跑基线，不能跨引擎冒充复现。

## 冻结与最终验收

1. 在开发窗完成比较，进入验证页选择一个成功实验、其中的固定因子和比较参照，填写名称后冻结。默认因子可由服务端取最后开发窗选择；页面明确选择具体版本。
2. 冻结记录绑定快照、因子、参照、持有期、选股数、成本、目标、样本门槛和代码摘要，不能覆盖。最终期仅计算该固定因子，不再择优、训练或调用模型。
3. 点击“最终验收”才计算留出期收益。信号从留出起点开始，下一月观察点入场，持有期结束后退出，使用非重叠窗口与同日期参照。开发期历史仅作因子预热。
4. 至少需要两个成熟信号窗口。3/6/12 个月持有期需至少 8/14/26 个月留出数据；工作台仍要求留出至少12月，所以6/12月研究须主动扩大留出窗口及总历史。样本不足保存失败，不算通过。
5. 暴露台账在读取留出收益前以 SQLite 事务预留。日期区间相交且股票有交集时，无论来源文字、因子、目标或快照修订如何变化，下一次验收都标为非独立，不能据此启用。提前冻结多个候选也不能绕过此限制。
6. 同一冻结记录再次请求返回原结果。失败也消耗区间；计算中断而未提交结果时保留暴露记录并禁止重跑该记录取得独立资格。应检查故障，再用未暴露的新时间段验收，不得删除台账重试直到通过。

台账只保护同一数据目录内的系统操作；不能识别外部查看原始数据、改代码、改库或更换数据目录。最终结果不进入 AI 协作包，AI 工具也没有最终验收/启用入口。用户若把最终反馈用于调参，需要新的未暴露数据。

## 人工启用、更替与回滚

只有通过独立最终验收的版本可人工启用。激活、更替、退役和回滚都记录实际生效时间、理由、前版本和目标版本；同时检查页面看到的当前版本，避免旧页面误覆盖。回滚目标必须曾经启用。

这是研究版本引用，不修改因子、实验、历史信号和标签，不产生订单。合成版本允许用于走通流程，页面和结果保留合成标识。引擎改变后暂停新启用/信号/标签更新，应恢复原环境或重新验证；查看旧记录仍然可用。

## 前向观察

1. 先启用研究版本，再导入追加的月度快照。点击“为当前版本生成研究信号”，只处理最新截面。
2. 新数据须延续冻结数据的类型、口径、数据性质及固定股票池，完整保留先前历史；有修订时拒绝静默接入，先核对并重新验证版本。
3. 截面必须在冻结数据结束之后，不在未来，距当前中国时间日期不超过45天。保存实际生成时间、因子版本、快照、所选股票、全池与费用。相同版本/信号日期幂等，不允许覆盖；切换版本时事务防止为刚退役版本提交信号。
4. 后续新快照到达后点击“更新所选版本成熟标签”。入场为下一月观察点，而且日期必须严格晚于实际信号生成日；否则拒绝事后成绩。退出为入场后指定月数，只有已经到退出日期且有数据才保存标签。
5. 观察页保留每个信号与标签，汇总时取按入场排序的非重叠窗口。至少两个成熟窗口且满足样本门槛后，才比较上涨比例/均值/尾部相对最终验收结果的变化，显示退化提示。期间不同，这只是描述性提示，不是统计显著性、概率校准或自动替换依据。
6. 已退役版本的历史信号仍可更新成熟标签。样本不足、数据质量拒绝和指标下降分别显示；没有自动优化或自动启用。

当前通过按钮触发月度信号与标签更新。已有每日在线日线下载不会自动生成月度面板、信号或 AI 提案；报价也不是成熟收益标签。日线转月度会舍弃最后日历月，应注意数据时效和下一观察点尚未到来的要求。

固定池、未经核验的公告时间/公司行动、常数成本、单笔而非组合的限制仍然存在。前向观察不是事后回放，也不能用合成单调面板的测试成绩证明真实有效。

## 接口和存储

- GET `/api/strategies/state`、`/versions`、`/forward/{strategy_id}`。
- POST `/api/strategies/freeze`、`/evaluate`、`/change`、`/signal`、`/observe`。
- 不可变产物：`freeze`、`final_evaluation`、`strategy`、`forward_signal`、`forward_label`。
- SQLite 台账：`final_exposures`、`lifecycle_events`、`forward_keys`，与原有实验保存在同一目录。
- 当前最终验收和前向更新为受请求计算锁保护的同步操作，尚未接入队列取消/超时。数据上限仍受现有 CSV/面板契约约束；长历史扩展时应先迁移到持久化任务。

备份前停止应用，复制整个数据目录，不能只备份产物而遗漏暴露与版本事件台账。
