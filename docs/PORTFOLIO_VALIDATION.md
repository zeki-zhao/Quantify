# 组合最终验收与人工版本

迭代012，2026-10-20（Asia/Shanghai）。入口 `/portfolio-validation`，导航“组合验证与版本”。本页与开发组合回放 `/portfolio`、单笔验证 `/strategies` 分开；最终结果不进入AI研究上下文。

## 操作顺序

1. 先在组合页完成当前引擎的开发回放；在本页选择该回放，冻结名称、完整组合规则、参照和组合准入政策。冻结不可修改，数据快照、成分因子、资金、费用、调仓相位和比较区间全部绑定。
2. 参照默认同资金、费用、调仓和现金目标的等权全池。也可选择绑定相同三类快照、边界和引擎的固定组合；资金及费用必须相同，选股数、调仓周期和现金目标可不同，作为明确冻结的策略差异。
3. 提交最终验收。后台从留出起点的纯现金账户回放，沿用原组合调仓相位；不搬入开发期持仓。查看实际净值、回撤、完整周期、费用与成交，导出冻结及完整账本。
4. 同时满足独立性、准入政策和成功任务交付后，人工首次启用或替换当前研究引用。回滚只能选曾经启用过且当前引擎仍有效的版本；退役清空当前引用。每项操作填写理由，保存实际操作时间及前后版本，不能回填日期。
5. 页面携带所见的 `expected_active`；其他操作已改变活跃版本时服务会拒绝陈旧请求，刷新后再操作。旧实验、账本和生效事件不被覆盖。

启用只记录组合研究版本，不连接交易、不迁移历史现金或持仓，组合前向账本与自动串联待后续建设。

## 冻结与时间边界

冻结必须来自成功开发回放及当前引擎组合版本；不接受原单笔验收结果替代组合资格。完整组合规则也可绑定011的多因子版本。

最终区间为源实验 `holdout_start` 至绑定月度快照最后观察点。开始时均为初始现金，月度因子只读当时及此前的历史，调仓信号收盘后于下一日线观察点开盘模拟；原100股、T+1、停牌/限价、费用、滑点及拒单规则继续使用。月度之前的日线用于价格一致性核对；最终日线执行与估值严格截止冻结终点，之后的日线即使已在快照中也不进入。

调仓相位锚定原开发组合的第一个信号，不在留出起点重新择优或优化相位。留出起点未落在调仓日时先持现金。期末保留持仓、不强平，期末未成交订单明确列出。固定池、用户声明、未复权价格不含分红、公司行动、真实交易日历与真实成交能力限制见[组合回放](PORTFOLIO.md)。合成结果只能验证流程。

## 组合准入政策

本页独立保存组合政策，不把单笔研究的 `positive_rate` 当成组合胜率。

| 配置 | 默认 | 含义 |
| --- | --- | --- |
| primary | positive_period_rate | 完整周期上涨比例；也可明确选total_return累计收益 |
| min_improvement | 0 | 主目标必须严格超过此改善幅度，含1e-12数值容差 |
| max_return_deterioration | 0 | 累计净收益相对参照最多允许下降 |
| max_drawdown_deterioration | 0 | 最大回撤相对参照最多允许恶化，回撤本身为非正值 |
| max_worst_period_deterioration | 0 | 最差完整周期净值收益相对参照最多允许下降 |
| min_periods | 2 | 候选和参照至少两个完整周期 |
| min_observed_days | 60 | 两账本至少60个观察日，且日期数量一致 |
| min_trades | 1 | 两账本均需至少一笔实际模拟成交，不能用全现金空结果取得资格 |

完整周期采用候选冻结调仓信号的收盘净值为共同端点：`终点权益 / 起点权益 - 1`，不重叠且含期间已发生费用。固定参照即使按别的频率调仓，也在同一组端点评估。上涨比例为收益>0的周期数/完整周期数，不是单笔胜率或未来概率；窗口相关，不提供独立置信区间或显著性。

完整周期末尾不够一个调仓间隔的尾段不纳入周期统计，但保留在全区间累计收益、回撤、成交和期末权益。冻结时若已知月度端点不足要求，会直接拒绝，避免无意义地消耗留出。运行后同时核对周期数量、观察日数量、实际成交和风险下限，最终 `accepted` 还要求本地独立性。

## 共享暴露台账与恢复

`exposures.reserve` 由组合和单笔最终验收共用，在计算留出标签/回放前以 `BEGIN IMMEDIATE` 事务预留股票集合与完整日期范围。组合键为 `portfolio:<freeze_id>`，沿用已有 `final_exposures` 表，不清理旧单笔记录。

- 相交股票和日期已被任一类最终验收预留，本次均非独立。改名称、因子、来源声明、目标、成本或数据版本不重置资格。
- 同事务检查当前目录内已成功的开发实验：若其开发区间已经覆盖目标留出且股票相交，也标为已暴露，报告列出 `development:<experiment_id>`。这项检查同样适用于单笔最终验证。
- 失败、取消、超时或进程中断后，预留仍保留。无完整结果时同一冻结版本禁止重新计算；新建冻结只能作为非独立探索性重测。取消发生在排队/预留前则尚未消耗暴露。
- 同冻结版本已有完整成功或失败报告时，后续任务读取不可变缓存，不重新回放或重新获得独立性。
- 完整报告在提交后、任务结束前被取消的窄窗口也不能绕过任务状态直接启用。显式新建重试成功交付该缓存后才可启用；不会再次读取留出计算。

独立性仅限本数据目录可观察的记录，无法识别用户直接读取快照、外部窥视、改代码、别的数据目录或更改证券代码伪装身份。它不证明真实市场有效。最终结果不向模型提供调参反馈；后续方案需新未暴露数据。

## API、任务与存储

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | `/api/portfolio-validation/freeze` | `development_run_id,name?,reference_spec_id?,objective?`，保存冻结 |
| GET | `/api/portfolio-validation/freezes` | 完整冻结版本列表 |
| POST | `/api/portfolio-validation/evaluate` | `freeze_id,timeout_seconds?`，提交验收或读取缓存的任务 |
| GET | `/api/portfolio-validation/evaluations` | 结果索引、独立性、准入与历史暴露；不含大型账本 |
| GET | `/api/portfolio-validation/evaluations/{id}` | 完整最终报告，ID等于freeze_id |
| GET | `/api/portfolio-validation/state` | 当前研究引用及追加事件 |
| POST | `/api/portfolio-validation/change` | `action,expected_active,reason,freeze_id?`；action为activate/replace/rollback/retire，退役不带目标 |

第七种任务 `portfolio_validation` 复用取消、超时、新建重试、启动中断和任务页，无暂停续算。队列成功表示完整报告已交付，可能是未通过或非独立报告，不能把任务成功当准入通过。

`portfolio_freeze`内容摘要校验，嵌入完整组合/参照绑定与政策；`portfolio_evaluation`不可覆盖，保存完整账本、独立性和决策；`portfolio_lifecycle_events`只追加。停机备份整个数据目录即可。旧引擎可查看报告，但不能跨引擎新验收或启用；应恢复冻结环境，或以新的研究和未暴露数据重新验证。
