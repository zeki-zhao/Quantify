# Quantify 构建与迭代文档

本目录是后续开发的计划与进度入口。当前保留合成 demo，并新增 CSV 研究工作台；在线真实数据尚未接入。规划中的能力只有在对应迭代完成并通过验收后，才能标记为已实现。

- [构建计划](BUILD_PLAN.md)：产品架构、真实数据接入顺序、因子迭代设计、里程碑和验收标准。
- [数据契约](DATA_CONTRACTS.md)：CSV 字段、价格口径、财务时点、增量与备份。
- [迭代目录](iterations/README.md)：每次迭代的状态、记录和下一步。
- [迭代模板](iterations/TEMPLATE.md)：目标、改动、验证、限制与交接格式。
- [项目交接](../HANDOFF.md)：当前实现状态与最近交接。

## 每次迭代的执行约定

1. 开始前阅读根目录 `AGENTS.md`、`agnet.md`、`README.md`、`HANDOFF.md`，以及本目录的构建计划和迭代索引。
2. 从构建计划选择一个可验收的范围，建立 `iterations/NNN-short-name/README.md`，填写对应计划编号、验收条件，并在索引登记为“进行中”。编号递增且不复用；如果工作分多次会话完成，继续更新同一条记录。
3. 实施时记录关键决策、计划偏离及原因。涉及数据源、模型或凭据的前置条件，应明确记录；凭据值和受限原始数据不写入 Git。
4. 按改动范围验证，记录实际命令、结果和未执行项。文档变更检查链接及 diff；核心计算变更运行现有测试；新增服务或数据流程应有代表性功能验证。
5. 收尾时同步更新迭代记录、迭代索引、`BUILD_PLAN.md` 的进度和 `HANDOFF.md`。开发约定改变时同步 `AGENTS.md` 与 `agnet.md`，用户用法改变时更新根目录 `README.md`。
6. 未达到验收条件的工作标记为“进行中”或“阻塞”，不得因为代码已写完就标记“完成”。计划变更另写入构建计划的变更记录，保留历史迭代结论。

本目录记录的是软件开发迭代。将来的 AI 因子实验属于应用运行数据，保存到实验存储中；开发迭代可以引用实验编号，但不要求每次模型调用都生成一份 Git 文档。
