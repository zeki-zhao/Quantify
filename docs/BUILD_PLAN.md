# Quantify 构建计划

更新日期：2026-10-14（Asia/Shanghai）

计划版本：v2

状态：第一阶段 CSV 研究基础设施已落地；在线真实数据、动态池收益评估与实际覆盖验收尚未完成。

## 1. 目标与边界

构建以因子持续迭代为核心的个人股票量化研究工作台，支持真实中国股市数据、可复现研究、因子更替和 ChatGPT 辅助实验。

研究主线：数据准备 → 因子管理 → 策略构建 → 实验比较 → 因子更新 → 持续观察。

- 初期面向低频股票研究，沿用当前 3/6/12 个月持有期；高频、逐笔与盘口研究不属于基础版本。
- 保留基本面、情景估值、GBM 风险模拟，以及合成数据演示；明确区分真实数据与演示数据。
- 个人本地使用，不建设多用户、付费系统或托管云平台；不连接券商、不自动交易、不主动发布网站。
- 数据服务与模型 API 是按需接入的外部适配器。现有离线 demo 应继续可用。
- 不以单一上涨比例优化全部目标；同时报告收益、成本、风险、稳定性和样本量。
- “自我迭代”是根据实验反馈更新因子与策略，不要求训练 ChatGPT 本身，也不承诺持续改善收益。

## 2. 当前基线与差距

已有：Python 3.10+ 标准库 HTTP 服务、原生前端、五股合成数据、基本面和估值、GBM 模拟、月度 CSV 导入、固定因子集合、滚动样本外研究、JSON/CSV 导出及 23 项测试。

迭代 001 已实现：CSV 数据契约和可替换适配接口、不可变快照、手动增量、财务与股票池时点查询、日线转月度、五类参数化因子版本、SQLite 实验持久化、结果对比和网页入口。

尚未实现：在线真实来源及覆盖验收、自动每日下载、动态池收益评估与退市处理、独立策略版本与启用、组合资金与成交核算、任务队列、AI 工具调用、实时行情和前向观察。

当前研究是“股票 × 入场月份”的单笔收益统计；不能据此声称已实现组合净值回测。`quantify/interfaces.py` 中相关协议不代表功能已完成。

## 4. 技术架构与持久化

采用模块化单体：网页 → 应用服务/API → 数据、因子、策略、实验、AI 模块。实验通过独立计算进程执行，结果返回报告模块。

- 继续使用 Python，核心计算与 UI、模型提供商解耦；原生前端先逐步拆分导航与页面。
- 已使用标准库 SQLite 存放数据快照、因子版本和实验记录；任务队列与独立策略版本后续扩展。
- 原始文件、不可变数据快照和报告保存在本地运行目录；大规模列式数据需求出现后再评估 Parquet 等依赖。
- 本地数据、数据库和凭据不得误提交到 Git；实现存储时定义忽略规则、备份与恢复流程。
- 长任务返回任务编号，支持查询、取消、超时和失败记录。进程退出后未完成任务应标记为中断；重试记录不得覆盖旧结果。
- AI 与人工操作调用同一应用服务接口，避免两套计算逻辑。

核心对象：

| 对象 | 必须保存的内容 |
| --- | --- |
| 数据快照 | 来源、时间范围、字段口径、文件摘要、可用时间、修订版本 |
| 股票池版本 | 当时可知的成员、生效时间、加入退出原因和退市处理 |
| 因子版本 | 稳定因子 ID、版本、父版本、公式/代码、参数、字段依赖、修改理由、摘要 |
| 策略版本 | 股票池、明确的因子版本、组合权重、选股与调仓规则、执行和成本假设 |
| 实验 | 上述版本、评估协议、引擎版本、随机种子、任务状态、指标、产物与错误 |
| 迭代任务 | 研究目标、允许修改范围、固定基线、预算、模型标识、提示词、工具调用、结论 |
| 启用记录 | 策略版本、生效时间、替换依据、前向结果与回滚历史 |

同一因子有多个不可覆盖的版本；修改因子不自动修改引用它的策略。策略必须绑定具体版本。启用与回滚只影响之后的观察，不改写历史实验或持仓记录。

## 5. 真实中国股市数据的实施顺序

真实历史数据从第一阶段开始；先日线与每日增量，盘中实时行情在第三阶段引入。

| 数据 | 用途 | 时机 |
| --- | --- | --- |
| 历史日线、成交量、公司行动 | 动量、波动、流动性和历史验证 | 第一阶段起步 |
| 财务历史及实际披露时间 | 质量、价值和时点可用性 | 第一阶段，取决于数据覆盖 |
| 历史股票池、退市、基准 | 减少幸存者偏差、统一比较基准 | 第一阶段 |
| 收盘后增量 | 更新信号、积累前向样本 | 第一阶段后半段 |
| 分钟/实时行情 | 监测、模拟成交、前向观察 | 第三阶段 |
| 逐笔/盘口 | 高频研究 | 不列入基础版本 |

第一份真实数据成果：选定一个明确股票池，接入数年日线，运行真实动量和低波动研究，并开始每日保存数据及信号；历史财务披露信息充分后再加入质量和价值因子。

实施要求：

1. 评估供应商的授权、历史覆盖、延迟、更新频率、费用和接口稳定性；尚未选定供应商，不预设已有数据权限。
2. 对历史下载、增量更新和实时订阅定义独立适配接口，避免因子依赖某家供应商。
3. 区分市场事件时间、公告实际披露时间、系统接收时间；财报更正与行情修订保留版本，不能覆盖当时可见数据。
4. 统一复权和分红口径，防止含分红指数再次叠加股息；记录交易日历、停牌和涨跌停状态。
5. 检查缺失、重复、异常、时间乱序及更新中断；快照可复现，增量更新幂等，失败可恢复。
6. 真实研究逐步支持动态股票池和退市。当前平衡面板限制解除前，相关结果必须明确样本范围和偏差，不能声称全市场有效。
7. 获得行情不等于获得未来收益标签。三个月持有期的标签需要等到退出时点后才成熟。

## 6. 因子生命周期和 ChatGPT 迭代

因子详情包括：定义、版本差异、单因子检验、组合增量贡献、策略引用与使用历史。

状态：草稿 → 检查通过 → 实验完成 → 候选 → 启用 → 退役；失败和被拒绝方案同样留档。

迭代流程：

1. 固定研究目标、基线、数据快照、股票池、成本和比较窗口。
2. 人工或 ChatGPT 提出有经济解释的假设，声明允许变动的公式、窗口、组合或权重。
3. 创建候选版本，检查输入字段、表达式、数据时点和计算结果。
4. 执行单因子与组合实验，读取系统计算的真实结果。
5. 比较成本、收益、尾部、稳定性及重复程度，保存接受或拒绝的理由。
6. 在轮数、候选数量、时长和模型调用预算内继续迭代，满足停止条件后形成候选策略版本。
7. 独立验收后启用，继续前向观察；版本替换需有预设准入规则和生效记录，初版由用户选择启用。

模型可以随时解释结果和提出假设；低频研究先按周/月安排实验，不因每次行情变化自动优化。数据质量异常应暂停相关实验，不能被当作因子失效依据。

AI 研究室采用“任务历史 / 对话与提案 / 实验进度与版本对比”的组织方式。工具接口规划：

- `get_research_context`：读取目标、数据能力、基线和约束。
- `list_factors`、`get_factor_version`：查询定义与历史。
- `create_factor_candidate`、`validate_factor`：创建和校验候选。
- `run_experiment`、`get_experiment_result`、`compare_runs`：提交任务和获取证据。
- `propose_strategy_update`：提出替换建议，不直接改写已启用策略。

优先应用内 OpenAI API 接入，同时保留研究包导入导出；之后可用 MCP 复用同一套工具供外部 ChatGPT/Codex 使用，具体取决于客户端能力与连接条件。ChatGPT 订阅不等于应用 API 凭据或额度。

初版使用受限公式表达式，不对模型文本直接 `eval/exec`。未来允许生成 Python 时，需要独立的隔离执行、资源限制和文件/网络权限边界；普通子进程不等于安全沙箱。

密钥在安全配置中保存。提供给模型的上下文优先使用字段说明、指标与摘要，遵守数据授权范围；模型不可自行编造实验结果，也不可读取封存的最终留出结果来指导持续优化。

## 7. 验证协议

训练区间用于拟合；滚动验证区间用于候选比较；最终留出区间只在方案冻结后用于独立验收。若留出反馈被用于修改方案，该区间即失去独立性，应记录并采用新数据验证。

- 保留训练标签成熟检查、前视检查、重叠标签处理和时间顺序验证；所有预处理和参数选择遵守相同时间边界。
- 固定同期、同池、同成本基准，记录所有候选及尝试次数，避免只报告获胜实验。
- 因子层报告覆盖率、秩相关、分组收益、时段/行业稳定性和因子间相关性；样本不足明确标记。
- 策略层同时报告扣费收益、换手、尾部和样本量；组合净值、组合回撤等指标必须等到组合资金和成交核算实现后使用。
- 中国股票执行模型逐步覆盖 T+1、适用的交易单位、费用、滑点、停牌、涨跌停及未成交处理。
- 每个实验可追溯数据、定义、代码和评估协议版本；失败、取消、中断和未运行不得标记为通过。
- 不以合成数据结果、单一涨幅指标或反复挑选后的最好结果承诺真实胜率。

下一次建议迭代：补齐 P1.2 的动态股票池/退市规则设计及验证；取得用户授权的真实 CSV 或数据服务后核验来源、交易日历、分红与财务历史覆盖。P2 可复用当前应用服务，但尚未启动。当前不宣称完整真实研究环境已就绪。
