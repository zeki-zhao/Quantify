## 1. 有证据的目标偏移：上涨比例未进入准入条件

原目标强调检验因子能否改善上涨比例，同时不牺牲平均收益和尾部。当前存在两套不同的目标：

- `quantify/research.py:144`：训练窗多因子择优依据上涨比例。
- `quantify/worker.py:87`：研究室候选更新依据平均净收益改善、相对原基线的最差单笔收益约束以及样本数一致；不检查上涨比例是否改善或下降。
- `quantify/lab.py:55`：目标是保存的自然语言；`lab.py:76` 提示词也说明不会将任意自然语言目标转成选择规则。

因此实现符合当前写明的均值准入规则，但与用户强调的上涨比例目标之间仍存在缺口，不能将 `improved` 解释为“胜率提高”。这不是计算出错，属于目标和验收标准未统一。

本次通过实际 `Lab` → 队列计算进程 → 实验 → 比较的两轮合成会话复现，目标文字设为“在平均收益和尾部不恶化的前提下优先提高上涨比例”：

| 阶段 | 上涨比例 | 平均单笔净收益 | 最差单笔净收益 | 系统判定 |
| --- | --- | --- | --- | --- |
| 原始动量基线 | 68.75% | 2.5225% | -18.0308% | 基线 |
| 低波动候选 | 68.75% | 3.4807% | -17.3412% | improved |
| 趋势/低波动组合候选 | 62.50% | 3.7636% | -11.3228% | improved |

第二轮上涨比例下降 6.25 个百分点，仍被接受。全部指标来自合成数据的 16 个“股票×入场月份”样本，仅证明规则行为，不代表真实市场收益。[复现结果](objective-reproduction.json)保留公式、指标、差值和父版本；运行时使用临时目录，没有写入用户数据。

建议新增结构化目标与显式约束：上涨比例主目标可配均值/尾部下限，均值目标则单独选择；训练择优、候选准入、UI 标签和导出采用一致且可追溯的政策。可先默认采用“上涨比例严格改善，均值和尾部满足约束”，不能通过解析目标文字暗中改变准入。

## 3. 自我迭代的额外限制

- 每个会话固定同一快照和协议，这是公平比较的保护；但没有跨新快照承接已冻结策略、保存前向信号的工作流。
- `research_tools.py:97` 始终将新候选挂在原基线的第一个因子下。本次复现中两轮候选的父版本相同，不能表达“第二轮由第一轮演化”的因子谱系；逐轮日志仍然存在。
- 候选实验将 `factor_ids` 设为单个新公式。公式可以组合支持的字段/函数，但没有带版本引用的多因子组合、权重搜索或“新增因子对既有策略的增量贡献”测试。
- 轮数、候选数、时限和无改进预算是计算资源保护；新建会话/重试会重置预算。缺少跨会话尝试汇总、等价候选去重和多重比较诊断，预算不是防过拟合证明。
- 当前指标报告了上涨比例、均值、最差单笔、样本量和分窗，但“最差单笔”不等于持有期或组合最大回撤，也没有盈亏比及成交层换手。

## 4. 已授权的调整与需要纠偏的差别

已授权调整：

1. 迭代 001 按用户回复先做 CSV 与可替换接口；真实在线延期。
2. 迭代 002 用户选择手动 ChatGPT 提案；模型 API 自动化延期。
3. 迭代 003 用户采纳自选股快照/东财日线前置和独立价格收益补充。

需要纠偏：

- 真实数据/动态池/财务尚未验收时推进了 AI 基础，软件可以开发，但不能沿用“阶段已完成”的大范围表述；验收必须拆成软件基础与真实研究条件。
- 判优目标从用户关注的上涨比例落到了固定均值政策，没有提供结构化切换或上涨比例约束，需优先调整。
- 因子生命周期、独立最终评估与诊断指标在总方案中存在，但缺少细化里程碑，容易长期滞后于页面和接口建设。
