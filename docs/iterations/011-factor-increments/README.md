## 实现与关键决策

- `factors.py`新增blend：嵌入具体叶子定义及ID，平均秩百分位加权；用户权重存数值和Fraction精确比值。新增/移除保留原成分相对权重，避免重复归一化把同分变成不同分。
- `increments.py`为纯计算；`increment_service.py`为固定请求、版本绑定、缓存、引用和队列服务。诊断与增量共用`development_data`，从快照直接切除留出，使用源实验实际成熟测试信号窗。源实验若多选，原组合仍固定重算，不读取每窗赢家作为原组合。
- 任一输入失败使整个配对窗拒算，各版本仅在共同窗口汇总；任何覆盖不足均不得判改善。按原结构化目标评估，报告保留负增量、样本差、选股重合及逐项移除。移除贡献不可相加，不是净值归因或因果效果。
- `factor_increment`不可覆盖，ID由请求及引擎摘要生成；缓存复现仍新建第六类increment任务。支持取消/超时/重试/启动中断，无暂停。引用查询覆盖成分、派生、实验、冻结目标/参照、组合版本及增量报告。
- 可选augment会话只接受唯一固定基线版本，原成分最多9个；每轮新公式加入原基线，权重冻结，不逐轮累加。候选实验与增量指标/覆盖一致后，继续相对当前最佳和原基线判优及额外约束。
- `get_factor_increment`只读当前会话候选，核对具体成分与占比；手动包及API反馈仅有聚合证据，`compact_increment`再白名单裁剪，不发送原始行情/逐窗选股收益/留出。
- 试验统计另计增量报告与任务；缓存不增报告，AI候选实验仍归原收益实验。重复定义签名纳入成分与归一化精确权重，不能把相同定义换名字后算作新独立证据。
- 新增`/increments`与导航；TaskWatcher及报告请求序号防旧响应覆盖，引用查询也核对当前版本。浏览器初验发现保存后的长版本号在手机溢出，增加换行后验证通过。
