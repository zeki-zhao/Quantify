## 实施与关键决策

- 新增 `portfolio_policy.py`：组合主目标默认完整周期上涨比例，可明确选累计收益；同时检查累计收益、最大回撤、最差周期、共同周期数量、共同观察日和双方成交门槛。周期以候选冻结调仓信号收盘权益为共同端点，尾段仅纳入累计收益/回撤。不给原单笔positive_rate套组合名称。
- 新增 `portfolio_lifecycle.py`：portfolio_freeze内容摘要校验，嵌入组合/可选参照/政策；portfolio_evaluation按冻结编号不可覆盖；portfolio_lifecycle_events只追加实际时间/前后版本/理由。
- 默认参照为同条件等权全池；可选固定参照需同三类数据、边界、引擎、资金和费用，允许选股数/调仓/现金目标作为策略差异；双方按同候选端点评估。
- `PortfolioService._inputs`默认仍只取开发窗；最终服务显式传冻结范围并保持原相位。留出从纯现金开始，下一日线开盘执行；沿用100股/T+1/显式状态/限价/费用与拒单，期末不强平。冻结终点之后日线不进入回放。
- 新增 `exposures.py`，将单笔和组合的计算前预留统一到final_exposures，组合键portfolio:hash；同事务还检查当前目录已成功开发实验的区间和股票。既有暴露记录保留。无结果的相同冻结版本禁止重算，新冻结只能非独立重测；有完整结果只读缓存。
- 第七种portfolio_validation任务复用取消、超时、新建重试与启动中断，无暂停。完整报告已提交而任务被取消的边界下，仍需显式重试成功交付缓存后才可启用，不重新回放。
- 人工activate/replace/rollback/retire携带expected_active与理由。首次启用和替换分开，回滚须曾启用且引擎有效；不回写账目/历史、不迁移持仓。
- 新页面 `/portfolio-validation` 和导航，沿用TaskWatcher和报告详情请求序号；研究室能查看/控制验收任务，但模型没有最终报告或启用工具。
