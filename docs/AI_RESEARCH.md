# AI 研究室：手动 ChatGPT 协作

迭代 002 按用户选择采用手动提案。运行不需要模型密钥、ChatGPT 订阅或联网；若使用外部 ChatGPT，由用户在其客户端提交协作包并复制回答。本程序没有远程模型调用，`ProposalProvider` 仅保留未来 API 适配契约。

## 操作流程

1. 启动 `python app.py`，从研究工作台创建/导入月度快照，选择因子运行基线。工作台运行与复现现在进入后台队列，离开网页仍会继续。
2. 打开导航中的“AI 研究室与任务”。选择已完成基线，填写目标、最多轮数/候选数、连续无改进停止轮数和累计计算秒数。
3. 创建会话后点击“生成协作包”，复制文本或下载 JSON，交给 ChatGPT。包内包含提示词、公式规范、固定协议、开发窗统计和历史反馈。
4. 粘贴 ChatGPT 返回的 JSON，点击“导入提案并排队验证”。每个合法候选建立不可变因子版本，在相同快照、窗口、成本和持有期下运行实验。
5. 查看每轮上涨比例、平均/最差单笔净收益、样本量、差值和拒绝原因。重新生成协作包，把真实引擎结果交给 ChatGPT，继续下一轮，或提交 `stop`。
6. 到达预算或停止条件后，只保存研究建议。因子在工作台因子库可查看和派生，实验可对比/导出；没有策略启用或自动交易。

本次迭代 003 又新增价格收益口径和数据契约，公式使用基线所绑定的价格/总回报序列。协作包会带上该口径及来源警告；价格收益不含分红、公司行动跳变未调整。没有财务输入时只能研究价格类因子；在线数据更新不会自动启动研究。

旧 P1/P2 实验仍可查看，但本次引擎新增了公式模块，代码摘要已经变化。请在工作台按旧参数创建新实验作为当前基线；“按原配置复现”仅接受完全相同的引擎版本，不跨版本冒充复现。

## 提案格式与公式

单个对象或对象数组，每批 1–10 条，不得超过会话剩余轮数。四个字段必须齐全，不能加入 Python 代码、工具名称或任意参数：

```json
{
  "action": "propose",
  "name": "趋势与低波动组合",
  "expression": "rank(momentum(12, 1)) - rank(volatility(6, 0))",
  "rationale": "检验较长趋势与近期低波动的组合是否改善开发窗结果。"
}
```

停止提案：

```json
{"action":"stop","name":"","expression":"","rationale":"目前没有足够依据支持新的假设。"}
```

- 字段：`quality`、`value`，必须在开发数据中完整且满足已有时点要求。
- 历史函数：`momentum(window, skip)`、`volatility(window, skip)`，两个参数必须为整数常量；窗口 2–24 月，跳过 0–6 月。只使用信号时点及过去，禁止负数/未来引用。
- `momentum` 是含分红指数的窗口收益；`volatility` 是月度对数收益总体标准差，低波动使用负号。
- 截面变换：`rank(expression)` 为 0–1 平均名次比例，并列取中位名次；`zscore(expression)` 为当前截面标准化，常量截面返回 0。
- 支持数值常量、括号、正负号和四则运算。公式最多 500 字符、80 个 AST 节点、12 层深度；常数绝对值不超过 1e6、计算结果不超过 1e12；除数绝对值小于 1e-12 则拒绝。
- 解释器按白名单计算向量，不使用 `eval/exec`。不支持属性访问、索引、任意函数、导入、循环或生成 Python；后台进程用于中断计算，不是任意代码沙箱。

语法正确不代表可计算或有预测力。字段缺失、除零、重复公式等会拒绝并记录；比较完整 AST 只去掉空白差异，不保证识别代数等价。因子版本保留父版本和理由，原始提案及失败原因保留在任务历史中。

## 选择规则与预算

基线固定数据快照、3/6/12 月持有期、选股数、往返成本、至少 12 月封存期和引擎版本。共同预热 30 月，候选单因子与基线在同一开发窗比较。基线也可包含多个训练窗择优因子，但每个新公式作为一个完整规则检验。

满足以下全部条件才更新“当前最佳”：

- 平均单笔净收益相对当前最佳提高，且严格大于指定最低改善值（浮点容差 1e-12）。
- 最差单笔净收益不低于原始基线减去允许下降值。
- 测试窗口、协议及样本数量一致。

UI 阈值单位是**百分点**，API 为小数收益（1 个百分点 = 0.01）。自然语言目标用于提出假设，当前选择规则不会自动翻译为组合回撤、换手或其他尚未实现的指标。

轮数、候选数、连续无改进轮数均为 1–10；累计计算时间为 1–3600 秒。合法 JSON 中的非法公式也消耗一轮、计入无改进次数；通过校验创建的因子消耗候选额度，之后实验失败仍计数。完成、未改善、拒绝和实验失败均留档。达到预算、连续无改进或 `stop` 时停止；尚未执行的批量提案保留在输入记录中，不标记为已评估。

等待人工粘贴和暂停期间不计时，启动计算进程及各段实际运行时间累计；页面显示已结算的累计时间。停止后重试创建新任务、重置预算并重新处理原提案，有 `retry_of` 指向旧任务。当前无远程调用和 token 费用；未来 API 适配必须另加调用次数、token、失败重试及费用预算，不能复用时间上限假装控制费用。

## 持久化与恢复

任务、事件、提案、因子、实验使用同一数据目录的 SQLite。一个数据目录只允许一个队列管理器，最多保留 50 个未结束任务，一次运行一个队列计算进程。研究会话支持暂停/继续/取消，单次实验支持取消；超时或停止会终止计算进程。旧同步接口保留供兼容，页面的新研究请求使用队列。

暂停从已保存检查点继续。若实验已经提交入库但任务未完成结果记录，再继续时复用该轮确定编号的实验，不重复创建；若计算尚未完成，则重新计算该候选。停止边界可能已经保存候选或实验，它们不会被删除或当作完成的任务；任务状态与实验状态分别报告。

正常退出会中断当前计算；重启后原先排队/运行的任务标记为 `interrupted`，不会自动重跑。等待输入与已暂停的会话保留。中断、失败、超时或取消后可新建重试；已完成记录不可修改。备份请先退出应用，再复制整个 `--data-dir` 目录。Windows 文件锁分支已实现，但本轮运行验收仅在 Linux 完成。

## 工具边界和限制

`ResearchTools.call` 提供 `get_research_context`、`list_factors`、`get_factor_version`、`validate_factor`、`create_factor_candidate`、`run_experiment`、`get_experiment_result`、`compare_runs`、`propose_strategy_update`。仅允许当前会话因子与实验，不提供原始快照或留出收益工具；提案不能选择新快照、成本或持有期。工具调用和失败记录在事件日志中。这是内部应用接口，尚未部署 MCP 服务。

协作包不包含原始行情行或封存期收益。封存起点日期和开发结束日期用于说明边界；本地用户仍能在数据中心访问自己的原始快照，不能把这一机制描述为已完成最终独立验证。质量/价值字段可用性检查遵守 P1 的输入约定，实际财务真伪和覆盖仍需人工核验。

本阶段仅用合成数据验证软件。固定股票池/单笔收益研究的限制不变，真实来源覆盖、动态池/退市、组合净值、实时行情、策略启用和概率校准仍待建设；反复比较开发窗的最佳结果不能证明真实胜率提高。
