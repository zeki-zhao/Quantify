# 数据流水线与前向观察

迭代013，2026-10-21（Asia/Shanghai）。入口 `/forward`，导航“数据与前向观察”。默认关闭自动运行，不连接交易、不自动更替、不调用模型。

## 使用

1. 在[单笔验证](VALIDATION_LIFECYCLE.md)或[组合验证](PORTFOLIO_VALIDATION.md)中，人工启用当前引擎、已通过独立验收的研究版本。
2. 在前向页选择跟踪类型，绑定日线来源根版本。组合还必须绑定显式执行状态；若原月度面板含财务因子，需绑定能复现其历史数值和可用时间的财务来源。历史股票池可选，当前仍拒绝动态成员变化。
3. 后续CSV增量导入选择同源链最新版本为父快照。系统沿绑定根版本的唯一后代链读取末端，不靠全目录最新时间猜测来源。分支会暂停，需核对来源；不自动合并分支。
4. 点击“验证并运行”，后台串联时间截取、质量检查、月度派生、实际信号和成熟标签/组合账本。查看每次运行及完整来源，导出JSON。历史运行按其绑定的不可变报告显示，不能被后续报告替代。
5. 需要自动化时显式“开启自动运行”：应用持续运行，中国工作日16:30后每约30秒检查来源追加。同日相同来源只提交一次；新来源版本会产生新的检查。关闭只停止后续调度，已有任务需单独取消。
6. 原有行情页的每日下载是独立开关，本页不会替你开启。若已经开启且下载追加到绑定链，流水线能检测新日线；CSV追加同样可用。公开行情不会自动补齐组合所需执行状态。

流水线绑定具体启用事件。更替、退役或回滚后旧流水线暂停，即使回滚到同一个冻结ID也不能继续旧事件。显式创建新流水线，组合观察账户重新从现金开始，不迁移或回写之前的持仓和观察。旧记录仍可查看。

旧引擎的冻结/启用不能跨版本续跑；应恢复原环境，或以新的研究及未暴露数据重新验证。一个目录只运行一个应用实例，备份需停机复制整个数据目录。

## 数据和时点

- 只读当前中国时间已完成日期：16:30前排除当日，周末回退至工作日。未来日期/尚不可用行不参与，必要时保存明确的时间截取快照；这不是交易所节假日日历。
- 日线固定池截面必须完整，不能补过期价、补零或静默删股。日线超过7个日历日、月度超过45日时等待新数据，不称为策略退化。
- 月度沿用既有“取共同最后观察点、舍弃最后日历月”的保守规则；只有后续月份观测到来后，前月才进入月度面板，不保证月末即时发信号。财务和股票池按声明可用时间连接。
- 根数据、最近成功输入和冻结历史须保留。历史修订、缺失、已观察区间回填、池/口径/演示标识改变会暂停；财务新披露允许追加，但不能改变已经绑定的历史月度面板。
- 组合仍按未复权价格、显式停牌/限价、100股、T+1、固定费用/滑点模拟。固定池、真实公司行动、真实交易日历及撮合限制继续保留。数据性质为合成或用户声明，不会转成真实验收标识。

## 单笔流水线

复用005的 `Lifecycle.signal/observe`，绑定生效事件序号，避免“换走再换回”的旧事件误续跑。最新月度截面必须在冻结之后且足够新，实际生成时间留档；流水线按启用事件/信息日去重，回滚后新事件不会复用旧时间戳；旧手动入口仍保留版本级历史。入场仍是下一月度观察点，必须严格晚于实际生成日。

每次追加先生成当前信号，再检查旧信号标签是否成熟。未来数据截取、退出时点与持有期检查不满足时保留等待，不补造标签。只有非重叠成熟窗口达到原政策样本要求才给下降提示；不足两个成熟窗口不告警。单笔统计仍不是组合净值。

## 组合前向账本

组合不重跑一条事后计算的选股路径。每次实际决策保存不可变的 `portfolio_forward_signal`：

- 绑定流水线、启用事件、冻结组合、当期月度信息、当前可用日线/执行状态；记录信息日、实际生成时间、生成日和最新已完成估值日。
- 沿用冻结组合调仓相位，参照也按自己冻结的相位；默认等权全池跟随候选。只在最新月份有新调仓需求时创建，不补齐过去漏掉的月份。
- 根据当时及以前的月度因子计算股票，用最新已完成收盘和当前观察账户权益冻结目标股数。候选/参照股数和费用规则保存，后续不重新排序或按未来开盘放大订单。
- 仅在**实际生成日期之后**的第一条完整日线开盘模拟成交。信号隔日/周末/延迟生成不会在已经过去的开盘成交。生成日当日也不成交，日期粒度下采用保守规则。
- 股数遇跳空或费用只缩减；停牌/限价等拒单不追单，继承既有成交规则。未到可执行日保留待执行，不虚构成交或强平。

之后按保存的订单重建累计Decimal账目。只能追加数据，既有曲线、成交和订单前缀必须完全一致；新报告不能回写旧账目。根版本或启用事件改变必须新建观察账户。相同输入不重复创建信号或报告，重试复用原信号的时间与数量。

成熟标签由相邻实际候选调仓决策的估值收盘端点产生：终点权益/起点权益−1，保存不可变 `portfolio_forward_label`，其成熟时间是终点决策实际生成时间。中间实际支付的费用计入收益，不完整尾段仍保留在累计净值。实际持有段时长可能因生成延迟不同，不能把它冒充固定月数的回测或独立试验。

报告展示候选与同期冻结参照、持仓、完整曲线、成交、待执行订单、成熟标签和来源。达到冻结政策周期数/观察日/成交门槛后，才检查主目标或累计收益/回撤/最差段是否低于同期参照；同分不算下降，样本不足不告警。提示只用于人工判断，不自动退役、调用AI或更替版本。

## 状态、失败和恢复

| 情况 | 显示与处理 |
| --- | --- |
| 无近期完整数据/前一决策待后续观察日 | waiting_data，等待；不判为退化 |
| 尚无调仓需求 | waiting_signal |
| 已有信号但成熟样本不足 | insufficient_mature_labels；单笔同时显示pending_labels |
| 数据完整、样本充足 | observing；组合发生下降时为degraded，单笔沿用观察状态并明确degradation字段 |
| 历史修订、回填、池/输入/执行状态问题 | data_quality，暂停自动调度，保留原有效报告 |
| 启用事件或引擎改变 | version_changed，须显式建立新绑定或恢复原环境 |
| 取消、超时、中断或意外执行失败 | execution_failed，需显式运行恢复；不会静默重试 |

每步检查点保存在任务中，信号/标签/报告分别不可变提交。取消不是跨所有阶段的撤销：可能已有合法信号留档；重试按原ID复用，不能重新生成较早的时间戳。没有完成记录的进程错误保留在任务中，并由流水线状态明确显示，不把旧观察结果当成本次成功。

即使进程在组合信号提交后、有效报告或运行记录提交前退出，重试仍须相对该信号保存的日线、执行状态与月度输入校验追加关系；不能借中断后修订数据改变原决策或成交。

自动调度以事务竞争“日期+来源版本”意图，队列内再次原子去重，同一流水线最多一个排队/运行任务。意图提交后进程退出也不静默重发，启动时孤立意图和未完成任务标为需恢复。修复数据后点击“验证并运行”，成功则解除暂停；开启开关本身不清除异常。

## API与持久化

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| POST | `/api/pipelines/specs` | `name,mode,daily_root,execution_root?,financials_root?,universe_root?`；绑定当前启用事件，默认关闭自动运行 |
| GET | `/api/pipelines/specs` | 不可变定义及调度/暂停/最近任务状态 |
| POST | `/api/pipelines/config` | `pipeline_id,enabled,expected_revision`，显式修改开关 |
| POST | `/api/pipelines/run` | `pipeline_id,timeout_seconds?`，提交第八种pipeline任务 |
| GET | `/api/pipelines/runs`、`/{id}` | 运行索引或完整结果/质量原因 |
| GET | `/api/pipelines/reports/{id}` | 不可变组合前向报告；历史运行绑定此ID |
| GET | `/api/pipelines/portfolio/{pipeline_id}` | 该流水线当前有效组合前向报告 |
| GET | `/api/pipelines/status` | 调度服务异常和运行说明 |

`pipeline.py`负责绑定、来源、串联、调度；`forward_portfolio.py`为已记录决策的纯账本重建。新增pipeline_spec/pipeline_run/portfolio_forward_signal/portfolio_forward_label/portfolio_forward_report产物，pipeline_state与portfolio_forward_heads记录当前状态和报告引用。pipeline任务支持取消、超时、新建重试及启动中断，无暂停续算。

本轮只验证软件和合成前向时间推进；没有实际积累真实持有期标签，不代表真实策略效果。真实来源/账户联测、动态池、公司行动、交易日历、行业和统计校正继续按构建计划跟踪。
